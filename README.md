# CS Pilot · 寄生式自动检测

在 **CS Studio6 / CS Studio5** 外部运行的小程序：不修改软件任何默认配置、不新增实验类型、不改协议，
只通过 Windows UI 自动化（UIA）读序列、填参数、点按钮，并用**独立的判稳算法**监视
数据（6 版读文件、5 版读界面），稳定后由本程序令软件停机，自动接续下一项。

> →停当前自动接续→文件心跳收尾）；四窗控件表 4/4 归档；空队列建队问题解决；
> 审查修复 20 条；GUI v2（步骤时间线+文件名预览+worker 线程）。详见

## 一、它解决什么

CS Studio 自带的「开路电位测量(OCP)」有两个问题：

1. 参数窗里的**测量终止条件**只有「基于电位」和「基于Δ电位」两种，
   前作的实测结论是：**界面写「and」但实际执行是"时间到就结束"**，漂移条件形同虚设。
2. 就算能停，判据也只是「Δ电位 < 3 mV/min」（6 版）或出厂未启用（`OcpState=False`、`DeltaMaxOcp=10`），
   **只看斜率不看波动**，漂移正负抵消时会误判。

本程序的做法（判据按行业标准定稿，见第五节）：

- 软件侧**关闭**所有自带停机条件（`use_delta_stop=False`）；
- 6 版后台 `tail` 软件正在写的 `.txt`（约每 3 秒 flush）；**5 版运行期间锁文件**，改读运行窗口的界面数值；
- 用「窗口斜率 + 窗口峰峰值 + 最短等待 + 连续保持时间」四重判据判稳；
- 判稳后点软件的「停止」按钮 —— 6 版软件的行为是**只中止当前实验并自动跳到序列下一项**；
  5 版没有序列，由本程序自己开下一项；
- 同时保留「最长等待」兜底（默认 1800 s），到时按当前值继续。

> 判稳算法来自 22 个真实 OCP 文件的回测：22/22 判稳、兜底 0/22、中位 245 s、
> 23 个扫描类文件 0 误判。

## 三、使用

### 1. 准备（每次开机一次）

1. 打开 CS Studio6，连上设备（或进「系统设置 → 进入演示模式」做无设备演练）。
2. 菜单「工作通道(C) → 通道1」，打开通道窗口。
3. 在这个通道窗口里**摆好序列**：
   - 第 1 行：`开路电位测量(OCP)`
   - 第 2 行：`动电位扫描(Tafel,LPR)` 或 `任意恒电位阶梯波(多电位阶跃)`
   - 两行的**勾选框都要勾上**，顺序不能颠倒。

> 程序**不会**替你新增实验行（「添加」对话框的实验下拉是 owner-draw 且条目顺序会随
> 使用历史漂移，无法稳定自动化）。序列由你摆一次即可，之后每次跑都复用。

### 2. 运行

```
cd D:\deepseek\cspilot-parasite
python gui.py
```

窗口里填：

- **样品型号**：用于文件名
- **试样面积**：cm²，会写进软件的「电解池参数 → 电极面积」
- **测试项目**：Tafel 或 Step（必须与序列第 2 行一致）
- **输出目录**
- 判稳参数（**两阶段 + 5 分钟快照，一般不用改**）：
  - ① **严格**（前 `600` s）：斜率 `< 1.0` mV/min、峰峰 `< 2.0` mV —— 很稳的话十分钟内就能停
  - ② **放宽**（`600` s 后）：斜率 `< 5.0` mV/min、峰峰 `< 5.0` mV、**5 分钟快照差 `< 15` mV
    —— 快照来自 ASTM G59「隔一段时间取一次 OCP 比较两次是否接近」的稳态思路，专治"缓漂"
  - 公共：窗口 `60` s、达标后保持 `120` s
  - 最长等待 `1800` s（兜底，到时按当前值继续）
  - OCP 测量时间 `1800` s（软件侧的兜底，必须大于判稳所需）

点「开始检测」。

### 3. 输出文件名

```
<日期>-<样品型号>-开路电位.txt
<日期>-<样品型号>-动电位.txt      （或 -阶梯波.txt）
```

即 `2026-11-01-XYZ-动电位.txt`。

## 五、已知约束

1. **实验运行中序列是锁定的**，双击打不开参数窗 —— 程序在配置参数前必须确保实验已停止。
2. OCP 参数窗的「测量时间」必须设得比判稳所需长，否则软件会先到时间自己停。
3. 目标文件若已存在，软件会弹「本次测量数据文件存在重复」覆盖提示 ——
   程序开跑前会自动给文件名加 `_2`、`_3` 序号避开（`runner.dedupe_paths` /
   `runner5.build_filenames5`）。**必须这样做**：覆盖瞬间旧内容不会立刻消失，
   文件 tail 会读到新旧混合数据污染判稳（实测同名重跑时判稳从 24.5 s 拖到 46.7 s）。
4. `.txt` 文件约 3 秒才 flush 一次，判稳的时间分辨率受此限制（对 60 s 窗口无影响）。
5. 内存里的判稳用**已落盘的数据**，不是软件界面上的实时值。
6. **CS Studio5 在实验运行期间独占锁文件**（`PermissionError`），读不到 `.txt`，
   所以 5 版改成读界面控件（`uiprobe.UiSampler`），数据源与 6 版不同。
7. 上一轮实验若还在跑，序列是锁定的，程序会先调 `stop_current()` 再重试；
   最多等 12 轮 × 6 s ≈ 72 s，超时后仍会尝试继续。

## 五之二、压力测试发现并修复的缺陷（2026-11-02）

累计跑了 5 轮端到端（6 版 Tafel ×3、6 版同名重跑 ×1、5 版 Tafel ×1）+ 2 轮中止测试，
全部通过。过程中查出并修掉 5 个真实缺陷：

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | `watch.poll()` 不检测文件变短 | 同名文件被覆盖重建时 `seek(_pos)` 越界，读不到数据 | 每次 poll 先比 size，变小就 `reset()` 重读 |
| 2 | 文件名冲突导致覆盖 | 软件弹「文件重复」提示并覆盖写入，覆盖瞬间新旧内容混合，判稳从 24.5 s 被拖到 46.7 s | 开跑前 `dedupe_paths()` 自动加 `_2`/`_3` 序号 |
| 3 | 去重序号累积 | 连续去重产生 `_2_2` 这种怪名 | 先剥掉已有 `_\d+$` 再算序号 |
| 4 | 中止只停了当前实验 | `abort()` 后序列自动接续，Tafel 立刻开跑并写出 2 KB 数据 | `_do_abort()` 循环停止直到序列可编辑（最多 6 次），并 `_sequence_idle()` 验证 |
| 5 | 5 版 `abort()` 完全不停实验 | 只把状态改成「已中止」，实验仍在后台采集 | 中止时显式调 `studio.stop_run()` |

R2/R5 两轮同名重跑验证：产物正确变成 `…-开路电位_2.txt`，第一轮 11035 B 数据完整保留。

## 交流阻抗（频率扫描-电位控制模式）

### 名称对照（两版叫法完全不同）

| 软件 | 菜单路径 | 说明 |
|---|---|---|
| CS Studio6 | 测试方法(E) → 交流阻抗 → **频率扫描-电位控制模式(Nyquist, Bode)** | 扫频率，直流电位固定 |
| CS Studio5 | 测试方法(E) → 交流阻抗 → **阻抗~频率扫描(F)** | 同上，是同一个实验 |

**注意别搞混**：这里"电位控制"指的是**电位被控制住**（固定在一个直流电位上），
不是扫电位。真正扫电位的是「电位扫描(IMPE, Mott-Schottky)」/「阻抗~电位扫描」，
它在**单频点**下测阻抗随直流极化电位的变化，用来测微分电容曲线和零电荷电位。

### 参数（两版字段 id 相同）

| 字段 | 5 版 id | 默认值 |
|---|---|---|
| 文件名 | `Control_FileName_Text` | — |
| 开路电位(V) | `Control_Ocp_Text` | 实测值，只读显示 |
| 直流电位(V) | `EISVSfrq_SineBias_Text` | 0（相对开路 = 不外加极化） |
| 电位基准 | `Vs_Combo` | 相对开路 / 相对参比 |
| 交流幅值(mV) | `EISVSfrq_SineAmp_Text` | 10 |
| 初始频率(Hz) | `EISVSfrq_InitFre_Text` | 100000 |
| 终止频率(Hz) | `EISVSfrq_FinalFre_Text` | 0.01 |
| 点/10倍频 | `EISVSfrq_TenTwice_Text` | 10 |
| 确定按钮 | `EISVSfrq_OK` | — |

⚠️ 这几个控件的 `element_info.name` 是**错位**的（软件自身问题），
写代码时必须按 automation_id 认，不能按 name 认。

### 流程

默认流程改为 **开路电位 → 交流阻抗 → 动电位/阶梯波**（GUI 里「④ 交流阻抗」勾选即启用）。

- **CS Studio5**：脚本自己串起来（S_OCP_* → S_EIS_* → S_T_*），因为 5 版没有序列概念。
  阻抗扫完判定结束的方式：运行窗口消失，或界面读数（点数/进度）停滞 30 s。
- **CS Studio6**：序列模式，序列需要是 **OCP 行 → 阻抗行 → 测试行** 三行。
  脚本识别到阻抗行就填参数，没有就跳过并记一条日志。
  OCP 判稳后停止 → 软件自动接阻抗 → 阻抗跑完自动接测试项（软件自带的序列接续）。

### 输出文件

命名为 `日期-样品-交流阻抗.txt`（6 版）/ `.cor`（5 版），与其他项目一致。

## 八、阶梯波（任意恒电位阶梯波 frmPotSquareWave，2026-11-05 新增）

参数窗 automation_id 为 **`frmPotSquareWave`**（两版同源，控件表 p131 实测采集）。
结构：初始电位(带持续时间) → 中间电位 1..10（各带启用勾选+数值+持续时间）→ 终止电位(带持续时间)，可循环 N 圈。

### 各版本支持情况

| 版本 | 支持方式 |
|---|---|
| **CS Studio5** | **全自动**。菜单 `测试方法(E) → 暂态极化(T) → 任意恒电位阶梯波`，脚本自己开窗填参开跑监视 |
| **CS Studio6（序列模式）** | 支持。需要**在软件序列里加一行**「任意恒电位阶梯波」（添加 → 测量方法 → 暂态极化，**加一次即被序列记住**，与阻抗行同一模式）。fill/monitor 代码已就绪，行存在即可跑 |
| **CS Studio6（直开模式）** | **不支持**（主工具栏没有该实验的直开按钮、「快速实验定制」固定 11 法里也没有、cboExp 下拉为虚拟化自绘无法稳定自动选型）。选 Step 时会明确报错并给出上面两条替代路径 |

### 参数（脚本写死值）

- 阶梯：`init=-0.2 V → final=0.5 V`，中间步按 `delta=0.05 V` 均匀生成；**中间步超过 10 个时自动放宽步长等分**（`step_ladder()`）
- 每步持续时间 `hold=60 s`，循环 `1` 圈，时间单位 `s`，极化电位基准 `相对开路`（与 Tafel 的 vs OCP 一致）
- 采样频率 `10 Hz`；面积/密度/温度与其他实验同一套电解池写入
- 结束判据：**走完全部步即止**（数据停滞约 20 s / 运行窗消失 / 超时兜底），不看电流判据

### 实测

- 5 版 OCP→阶梯波（175.6 s）与 OCP→阻抗→阶梯波（272.3 s）全流程通过；
  `.cor` 头部证实参数精确写入：`ExpType=ID_PotSquareWave&-&Initial_E=-0.1&-&Step1=-0.05&-&Step2=0&-&Step3=0.05`

## 九、CS Studio6 直开模式（2026-11-05 新增）

**不用摆序列**：用主工具栏按钮直接弹参数窗，点确定立刻开跑，脚本自己接续。
动机：「添加」对话框 cboExp 是虚拟化自绘下拉（CB_GETCOUNT=0、键盘 type-ahead 无效、
点击读回值是悬停预览、点浮层外回退），无法稳定自动加行。

- 主工具栏按钮（tooltip 实测）：[1] 开路电位、[3] 动电位扫描、[5] 频率扫描-电位控制模式
- 流程：OCP（判稳自行停）→ 阻抗（剩余时间 0 / 点数稳定自行停）→ 测试项（电流密度 1e-3 A/cm² 或数据停滞自行停）
- GUI 软件版本选「CS Studio6直开」即用此模式；序列一字不改
