# 多通道模式重做方案（fleet 架构 v2）

> 2026-11-07 · 取代 monitor.py 单机看板方案与早期多通道讨论。
> 病根：旧模式下 runner 进程 detached 后**无人监督**——死了就死了、实验没人收尾、
> 状态散落在各自日志里，出现"后台被遗忘几台"的现象。

## 一、病根分析（为什么要重做）

| 旧模式症状 | 根因 |
|---|---|
| 后台被遗忘几台 | runner 是 detached 孤儿进程：死了无人知道、无人复活 |
| 状态要逐台翻日志 | 没有统一状态流；日志还是共享追加文件（互相交织） |
| 启停全手动逐台点 | 没有编排层；启停动作不原子 |
| 实验失控无人管 | runner 死后「扫描完成不自动停止」无人点停止键 |

## 二、新架构：fleet 编排器 + 受监督 runner + 统一界面

```
┌────────────────────── fleet_gui.py（统一界面）─────────────────────┐
│  [JK-O 卡片]   [JK-N 卡片]   [JK-P 卡片]   [JK-Q 卡片]              │
│  状态/步骤/指标  启动|停止|跳过OCP   心跳年龄   产物                  │
│  全局工具栏：全部启动 · 全部停止 · 排列软件窗口 · 急停                 │
└──────────────────────────┬───────────────────────────────────────┘
                           │ 每 2s 汇聚各机 heartbeat.json
┌──────────────────────────┴───────────────────────────────────────┐
│  fleet.py（编排守护进程）                                          │
│  · machines.json 机器清单：name/version(6|5)/port/sample/area/chain │
│  · 每机一个受监督子进程：python runner6_live.py <args>              │
│  · 监督：进程死亡→带退避自动复活（复用断点续跑）；连死 3 次熔断告警    │
│  · 心跳监督：heartbeat.json 超 30s 未更新→标记失联+告警              │
│  · 全局急停：逐台 stop → 验证数据停写                                │
└──────────────────────────┬───────────────────────────────────────┘
     ┌─────────────────────┼─────────────────────┐
     ▼                     ▼                     ▼
 runner6_live(CS6)  runner5_live(CS5#1)  runner5_live(CS5#2) ...
     │                     │                     │
 CS Studio6@COM16     CS Studio5@COM6      CS Studio5@COM11 ...
     │                     │                     │
 [通道1] 运行窗        [通道1] 运行窗        [通道1] 运行窗
```

## 三、关键机制

### 1. 心跳与断点续跑（解决"复活后重头跑"）
- 每个 runner 每秒写 `heartbeat.json`：`{stage, data_file, ts, pid, sample}` 到
  `_auto\hb\<机器名>.json`
- runner6_live/runner5_live 增加 `--resume`：启动时读自己的 heartbeat——
  * stage=动电位扫描中 且 数据文件仍在增长 → 跳过启动，直接进监视判流
  * stage=OCP 扫描中 且 文件仍在长 → 直接进监视
  * 否则正常从头跑（OCP→…）
- 编排器复活 runner 时自动带 `--resume`

### 2. 单实例与多实例并存
- 每套软件一个锁：`cspilot_cs6_runner.lock` / `cspilot_cs5_runner_<N>.lock`
  （3 台 CS5 各一个锁名，编排器按机器清单分配锁名）
- 编排器自己也有锁（fleet 本身单实例）

### 3. 软件窗口自动排列
- N 台机器的主窗按槽位排（第 i 台 → (i×480, 0, 480, 1000) 或 2×2）
- 泛化 position_windows.py → `arrange_windows(count)`；每次编排器启动/复活时调用

### 4. 5 版的界面取数隔离
- 5 版 runner 靠读运行窗界面取数：**窗口绝不能最小化**（编排器监督最小化事件，
  自动还原——driver5.ensure_main_visible 已有，保持 tick 内调用）
- 6 版 runner 读文件，最小化无影响

### 5. 串口模拟工作站（无硬件测试层）
- 6 版：`make_alias2.py COM16`（DOS 别名→CNCA0）+ `testbed/simdevice.py CNCB0`
  → CS Studio6 走正常模式发现"CS350M"并连上 → 全链无硬件可测
- 模拟器支持**回放真实数据**：从 CS-Pilot数据 的 .txt 加载历史曲线作为信号源
  （simdevice 增加回放模式）
- 5 版：CS120 协议（CST520 帧）与 6 版不同——需要先抓真机帧定格式（挂起，
  见"挂起项"）

## 四、实施批次

| 批次 | 内容 | 验收 |
|---|---|---|
| F1 | heartbeat.json 输出 + --resume 断点续跑（runner6_live/runner5_live） | 杀进程→复活→不重跑已完成的实验 |
| F2 | fleet.py 编排器（机器清单/监督/复活/急停/心跳汇聚） | 4 机配置离线编排测试（不碰软件） |
| F3 | fleet_gui.py 统一界面（卡片/启停/排列/急停） | 双实例演示模式全链 |
| F4 | simdevice 回放模式（真实数据复放） | 回放 JK-F 的 OCP/Tafel 曲线 |
| F5 | 5 版模拟器（依赖 5 版帧格式，挂起待真机抓帧） | — |

## 五、挂起项

- 5 版（CS120）帧格式：需真机抓帧或反编译 CS Studio5 的 Connect 程序集
- 「设备共享」语义（系统设置菜单里有此项，可能与多连接有关）
- Control_Ocp_Text 外部写入被拒绝（回读空）——真机确认该字段的自动填充时机
